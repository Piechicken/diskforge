> **DiskForge дает образам дисков настоящее рабочее место на рабочем столе.** Создавайте, проверяйте, просматривайте, извлекайте, внедряйте, конвертируйте, проверяйте и безопасно восстанавливайте образы, не сводя физический диск к второстепенной роли.

## Языки интерфейса

В DiskForge v0.10.0 локализованы рабочее пространство документов и шаблон FAT, безопасный импорт загрузочного кода, редактируемый fixed-VHD, выбор разделов, безопасная замена ISO, устаревший ZIP-контейнер, монтирование только для чтения, устройство MBR, сменные носители, контроллерная дискета и защищенные пути UFI USB-дисководов во время выполнения. Выберите **Tools → Language**, чтобы немедленно переключаться между шестью рабочими языками ООН — **Arabic, Chinese, English, French, Russian и Spanish** — плюс **Japanese**. Предпочтение сохраняется для следующего запуска. При выборе арабского весь макет Qt переключается на режим справа-налево, при этом технические значения, такие как пути к устройствам, контрольные суммы, расширения файлов и фраза подтверждения физической записи `ERASE`, сохраняются без изменений. Покрытие UI UFI не означает завершенного принятия форматирования на реальном оборудовании.

См. [LOCALIZATION.md](docs/LOCALIZATION.md) для матрицы языков, поведения RTL, границ безопасности и процесса поддержки переводов.

## Что он делает

DiskForge объединяет самые полезные рабочие процессы управления образами в одном оригинальном, поддающемся аудиту приложении. Главное окно сочетает проводник образов, таблицу каталогов, панель метаданных образа, журнал активности и область прогресса с возможностью отмены. Разрушительные действия визуально отделены от обычного просмотра и требуют явного подтверждения.

| Рабочий процесс | Родная возможность | Примечания |
|---|---|---|
| Создание образов | RAW/IMG/IMA, FAT12, FAT16, FAT32, проверенные устаревшие профили дискет FAT12, FAT12 с разметкой DMF, шаблоны FAT, ISO9660/Joliet/Rock Ridge/UDF, необязательный классический HFS | Создавайте редактируемые FAT-образы из стандартных предустановок, проверенного шаблона FAT BPB или явных устаревших профилей дискет IMG/IMA. Каталог устаревших форматов охватывает обычные совместимые с ПК разметки от 160 КиБ до 2,88 МиБ и поддерживаемую настраиваемую геометрию CHS. ISO-носители можно создавать из локального каталога с необязательным загрузочным носителем El Torito. При явном наличии `hformat` DiskForge может создать новый автономный классический HFS-образ обычного файла от 800 КиБ и выше; HFS+ остается только для чтения. |
| Просмотр и извлечение | FAT12/16/32 — включая проверенные немаркированные устаревшие дискеты DOS и RAW-псевдонимы `.vfd`/`.flp`/с суффиксом емкости обычного размера — консервативные кандидаты удалённых корневых файлов FAT12/FAT16; чтение IMD, TD0, CPC DSK, D88, APRIDISK, CopyQM, SAP, MSA, PSI, DC42, 2MG/2IMG, HFE, PRI, ограниченного 86F, FDI, JV3, DMK, UDI v1.0, стандартного SCP, канонического контейнера HxC MFM, канонического контейнера потока PCE PFI v0, канонического контейнера Apple II WOZ 2.0/2.1, канонического контейнера потока A2R 3.x, канонического контейнера G64 v0 1541 GCR, канонического двухстороннего контейнера G71 v0 1571 GCR и канонического контейнера P64 v0 1541 импульсов NRZI только для инспекции; ISO9660/Joliet, безопасные ZIP-контейнеры с несколькими образами и явным выбором, представления данных fixed VHD, а также необязательная поддержка только для чтения NTFS/EXT2/EXT3/классического HFS/HFS+ | Обычный ZIP с одной–64 безопасными корневыми полезными нагрузками образов материализуется только во временную приватную сессию только для чтения с автоматической очисткой. Одна нагрузка открывается напрямую; для ZIP с несколькими образами необходимо явно выбрать одну нагрузку в настольном приложении, CLI или SDK. Он никогда не становится доступным для записи или конвертации. Устаревшие RAW-псевдонимы классифицируются только когда их суффикс и точный размер в байтах соответствуют обычной 512-байтовой форме PC-дискеты; носители с переменными секторами, XDF, GCR, жесткими секторами и потоком не угадываются. Детерминированные постраничные деревья и сортируемые таблицы избегают неограниченного рендеринга каталогов. Проверенные разделы MBR/GPT всегда выбираются по явному индексу в таблице: FAT сохраняет свой существующий путь редактирования, в то время как NTFS/EXT/классический HFS/HFS+ открываются только по их точному проверенному смещению через бэкенд только для чтения. Двойной щелчок открывает неисполняемое рабочее пространство документа для текста, изображений, распространенных архивов, устаревших установочных пакетов, исполняемых файлов и двоичных данных. Текстовые документы можно искать, сохранять как копию и — только для записываемых записей FAT — редактировать и сохранять обратно. Fixed VHD обычно открывается через временное представление данных RAW только для чтения; проверенная независимая копия fixed-VHD может быть повторно открыта как записываемая сессия FAT. |
| Инвентаризация каталогов с образами | Сканирование метаданных локальных образов только для чтения с отчетами в форматах JSON, CSV или HTML | Сканируйте один локальный каталог, при необходимости рекурсивно, и отфильтровывайте известные кандидаты-образы по суффиксу, распознанному формату, файловой системе, диапазону байт или префиксу SHA-256. Перезапись SHA-256 по каждой записи и сводки по разделам — опциональны. Каждый отчет — это новый файл за пределами сканируемого корня; ни один кандидат-образ не изменяется. |
| Изменение содержимого образов | Внедрение в FAT, явное создание пустых каталогов, рекурсивные папки, удаление, переименование, копирование файлов и деревьев каталогов между каталогами плюс контролируемое перемещение, отметки времени, атрибуты DOS и метки томов; безопасные правки ISO на основе перестроения; опциональное контролируемое внедрение NTFS/EXT/классического HFS | Допустимые полезные данные FAT внутри IMG и IMA используют один и тот же путь редактирования. Пустой каталог можно явно создать только по новому пути, родитель которого уже существует; это никогда не перезаписывает и не создает неявных родительских каталогов. Обычный файл или целое дерево каталогов можно скопировать в существующий каталог без перезаписи; копирование сохраняет источник, требует новый одноименный целевой путь и отвергает целевой каталог, расположенный внутри исходного дерева. Файл или дерево каталогов также можно переместить в такой целевой каталог: для дерева каталогов сначала выполняется отменяемое копирование, затем удаляется источник. Отмена до удаления или неудача при удалении сохраняют оба полных дерева для ручного разрешения, поэтому перемещение каталогов не считается атомарным. Отсутствующие/не-каталожные цели, перемещение корня, конфликты имен, сессии только для чтения и цели внутри исходного дерева отвергаются до изменений. Переименование в том же каталоге остается отдельным действием. Явное удаление FAT удаляет один проверенный по пути некорневой файл или дерево каталогов; оно необратимо и не заявляется как транзакционное. Изменения ISO всегда записываются в отдельный перестроенный образ и проверяют подготовленное содержимое. Профили Rock Ridge/UDF сохраняются; перестраивается только проверенный каталог El Torito с одной записью, в то время как многозагрузочные, гибридные и неоднозначные схемы загрузки отклоняются. При явном наличии `ntfsprogs`, `e2fsprogs` или `hfsutils` NTFS/EXT/классический HFS могут получать новые обычные файлы в корне только в отдельно проверенном выходном образе; запись в источник, по смещению раздела, метаданные, переименование, удаление и перезапись не допускаются. Внедрение в классический HFS переносит только «data fork» (данные), HFS+ остается только для чтения. |
| Конвертация форматов | RAW/IMG/IMA и fixed VHD нативно | IMG и IMA сохраняют явно выбранное расширение сырого образа при конвертации. VHDX, VMDK и QCOW2 используют явно настроенный адаптер `qemu-img` с видимым отчетом о возможностях и поддержкой отмены. Отдельно настраиваемый адаптер `dmg2img` может только создать новый RAW-выход из DMG; DiskForge не монтирует и не записывает файлы DMG. |
| Компактизация FAT-образов | Дефрагментация на основе перестроения | Записывает новый образ, сохраняя исходный как точку восстановления. |
| Инспекция и ремонт структур | 512-байтовый шестнадцатеричный просмотрщик/редактор, проверенные свойства загрузки FAT, исходные нейтральные/сообщенческие шаблоны, нейтральная обертка MBR и планирование развертывания для образов FAT superfloppy, обрезка копии по замыкающим нулевым секторам, резервное копирование/восстановление/нейтральный сброс MBR и диагностика CRC GPT | Полные резервные копии образа или MBR создаются перед защищенными структурными изменениями. Шаблоны сохраняют поля BPB и не используют импортированную загрузочную программу; обертка, подготовка к развертыванию и обрезка всегда записывают новый файл. |
| Проверка и автоматизация | SHA-256, побайтовое сравнение, графическая студия пакетных «рецептов», планы предварительной проверки (preflight), просмотр результатов по каждому элементу, версионированные рецепты JSON и отчеты по директориям | Схема v4 добавляет декларативные `iso_edit`, `ntfs_inject`, `ext_inject`, `hfs_inject`, `hfs_create`, `export_listing`, FAT `move`, `fat_mkdir`, `fat_copy`, `fat_rename`, `fat_delete` и FAT `fat_metadata` с явными путями; все записи рецептов можно предварительно просмотреть перед выполнением, а записи на «сырые» устройства остаются запрещенными. `export_listing` создает только локальный текстовый/HTML-отчет и может нацеливаться на явно выбранный раздел только для чтения. Текстовые/HTML-отчеты по каталогам используют один стабильный полный обход для каждой просматриваемой ФС и явного раздела только для чтения. Визуальный конструктор охватывает конвертацию — включая выбор цели IMA — валидацию, сравнение, изменение размера, внедрение, создание классического HFS, извлечение и сценарии контейнеров. Сравнения могут опционально сообщать только полностью завершающие нулевые секторы как игнорируемые. |
| Аннотирование и изменение размера | Комментарии к образу без изменения оригинала и безопасное изменение размера RAW/FAT в новый файл | Сырые образы отклоняют сжатие, если пришлось бы отбросить ненулевые хвостовые байты. |
| Сборка распространяемых пакетов | Аутентифицированные многообразные контейнеры `.dfb` и проверенные по SHA-256 многообразные самораспаковывающиеся архивы `.pyz` | `.dfb` поддерживает необязательное шифрование AES-256-GCM на основе scrypt, сжатие, комментарии и проверку по файлам. | Чтение и запись физических носителей | Потоковое создание образов устройств и восстановление | Отклоняет системные диски, смонтированные цели и несоответствия емкости; требуется подтверждение вводом текста. Обнаруженные оптические носители доступны только для чтения и по умолчанию экспортируются в ISO. |
| Низкоуровневое форматирование дискет | Бэкенды Linux-контроллера гибких дисков и обнаруживаемые UFI USB-дисководы | `fdformat` ограничен стандартными узлами контроллера. Кандидат UFI USB должен быть связан в sysfs со сменным носителем, подтвердить себя через `ufiformat -i`, использовать явно сообщенную емкость и фразу `FORMAT_FLOPPY`, а также всегда проверяется с `-V`. Создание FAT остается отдельной, заново подтверждаемой операцией; фактическая приемка реальным оборудованием по-прежнему требуется для каждой модели привода. |

FDI v2.0, DMK, канонический HxC MFM, канонический PCE PFI v0, канонический WOZ 2.0/2.1, канонический A2R 3.x, канонический G64 v0, канонический G71 v0 и канонический P64 v0 — это только структурные инспекторы контейнеров для чтения: ни один из них не декодирует дорожки, битовые потоки или поток, не открывает файловую систему, не конвертирует, не ремонтирует, не записывает и не реконструирует данные RAW. JV3 также доступен только для чтения; он создает отдельный RAW-выход только после того, как обычные секторы докажут один полный прямоугольный макет с фиксированной геометрией. Каждый другой вариант исторических контейнеров остается сохраненным только для инспекции или отклоняется вместо угадывания или «выравнивания».

## Прежде всего безопасность

> Утилита для работы с образами дисков должна делать опасные операции **сложными для случайного запуска**.

DiskForge никогда не монтирует образ и не записывает физическое устройство автоматически. Развертывание FAT сначала создает просматриваемый нейтральный образ с MBR; оно не обходит защищенный путь физической записи. Перед физической записью проверяются емкость, состояние монтирования и статус системного диска, затем требуется точная фраза `ERASE`. Путь записи может проверить байты после завершения. Изменения в загрузочном секторе также сначала создают полную резервную копию образа. Всегда работайте с одноразовыми тестовыми образами перед операциями с невосполнимыми носителями.

## Портативная конфигурация

Используйте `diskforge --portable`, чтобы записывать настройки, выбор языка, последние образы, режим просмотра, тему, шрифт и путь к внешним инструментам в `DiskForgeData/diskforge.ini` в текущем каталоге. Используйте `--portable=DIR`, `--portable-directory DIR` или `DISKFORGE_PORTABLE_DIR`, чтобы указать явное местоположение. Этот режим использует обычный портативный INI-файл и не требует записи в системный реестр.

## Начните за считаные минуты

### Запуск из исходников

```bash
python -m pip install -e '.[dev]'
diskforge
```

### Использование командной строки

```bash
diskforge-cli create-fat demo.img --size-mib 32 --fat 16
diskforge-cli info demo.img
diskforge-cli list demo.img
diskforge-cli list partitioned.img --partition 2
diskforge-cli export-listing partitioned.img partition-report.html --html --partition 2
diskforge-cli mkdir-fat demo.img /DOCS  # один новый пустой каталог; родитель должен уже существовать
diskforge-cli copy-fat demo.img /README.TXT /DOCS  # сохраняет источник; файл или целое дерево каталогов; без перезаписи
diskforge-cli move-fat demo.img /README.TXT /DOCS  # /DOCS должен существовать; для каталога — отменяемое копирование, затем удаление
diskforge-cli delete-fat demo.img /DOCS/OLD.TXT  # один явный некорневой файл или дерево каталогов; необратимо
diskforge-cli set-fat-metadata demo.img /README.TXT /DOCS/NOTES.TXT --hidden --modified 2024-06-15T12:34:56  # только явные записываемые пути FAT
```

DiskForge честно показывает неподдерживаемые пути редактирования вместо попыток небезопасной записи. Инспекторы исторических контейнеров намеренно являются специфическими для формата контрактами только для чтения: HFE, PRI и ограниченный 86F не декодируют битовые потоки и не производят RAW; DC42 и 2MG/2IMG экспортируют только независимо проверенные области данных; APRIDISK, CopyQM, SAP, MSA и PSI экспортируют новый RAW только после того, как их индивидуальные парсеры докажут нормальные полные прямоугольные данные. Каждый такой контейнер отклоняет записи в источник, общую конвертацию, сессии файловых систем, существующие целевые выходы, устройства, ремонт и неподдерживаемые варианты. Пакетная инвентаризация — это локальный рабочий процесс создания отчета только для чтения, а не форензик-сканер и не безнадзорное изменение: он принимает один существующий не-символьный каталог, игнорирует ссылки, распознает только известные суффиксы образов, находит не более 10 000 обычных файлов, исключает файлы более 16 ГиБ и записывает только новый отчет JSON/CSV/HTML вне корня сканирования. Он не монтирует образы, не инспектирует физические устройства, не перезаписывает отчеты и не входит в схему пакетных рецептов v4. IMD инспектируется как контейнер дискетных секторов и не рассматривается автоматически как «сырой» или записываемый файловый образ. Новый RAW-файл можно экспортировать только из полного прямоугольного макета CHS с фиксированным количеством/размером секторов, последовательными идентификаторами `1..N`, без необязательных карт и с обычными (включая нормальные сжатые-заполнитель) данными секторов. TD0 аналогично является контейнером секторов, а не «сырым» или записываемым файловым образом: инспектируются только обычные несжатые записи `TD` с проверкой CRC заголовка/комментария/дорожки/сектора. Новый экспорт RAW дополнительно требует точного EOF, неотмеченных секторов, совпадающих физических и логических CHS, фиксированной геометрии и точной реконструкции обычных данных «raw»/повторяющихся шаблонов/RLE. Расширенно-сжатые `td`, многотомные записи, сбои CRC, флаги или отсутствующие данные, смешанная плотность, нерегулярная геометрия, перезапись выхода, запись TD0, редактирование, ремонт, устройства и утверждения о битовом потоке/флюксе отклоняются. Нерегулярная геометрия, отсутствующие/удаленные/плохие секторы, переменные макеты, дублированные записи, карты, хвостовые байты, целевые устройства, перезаписи, запись IMD и любые утверждения о битовом потоке/флюксе отклоняются. Восстановление удалённых файлов FAT — это узкий рабочий процесс **копирования кандидата**, а не общая форензик-реконструкция: он принимает только обычные 8.3-слоты фиксированного корня FAT12/FAT16 с положительной полезной нагрузкой не больше одного кластера и текущим свободным стартовым кластером. Удаленный первый символ имени файла недоступен; байты кандидата могут быть устаревшими или перезаписанными, поэтому не заявляется ни исходное имя, ни целостность. FAT32, подкаталоги, длинные имена, нулевые и многокластерные цепочки, занятые кластеры, запись в источник, перезапись существующего выхода, восстановление на устройства и пакетное восстановление отклоняются. Обычный ZIP — это узкий **контейнер образов только для чтения**, а не общая файловая система или источник конвертации: он может содержать от одной до 64 безопасных корневых нешифрованных полезных нагрузок Stored/Deflated с одобренными прямыми расширениями образов, каждая не более 2 ГиБ. Единственная нагрузка открывается напрямую; несколько нагрузок требуют точного явно выбранного имени корневого уровня в настольном приложении, CLI или SDK. Папки, небезопасные имена, шифрование, неподдерживаемое сжатие, пустые/слишком большие/неизвестные полезные данные, более 64 записей, рекурсивные контейнеры, цепочки виртуальных дисков, конвертация и любая запись ZIP отклоняются; временные байты удаляются при нормальном закрытии, ошибке и отмене. Перемещение FAT принимает один обычный файл или полное дерево каталогов и один существующий целевой каталог; оно никогда не перезаписывает и не объединяет записи. Деревья каталогов используют отменяемое копирование-затем-удаление; отмена до удаления или ошибка удаления сохраняют оба полных дерева, поэтому операция не заявляется как атомарная. Пакетные обновления метаданных FAT ограничены явно перечисленными существующими записями в записываемом образе FAT или явно выбранном разделе FAT. Они могут устанавливать или очищать только стандартные биты «read-only», «hidden», «system» и «archive» и применять предоставленные вызывающим временá FAT без учета часового пояса для создания, изменения или доступа. Пустые запросы, корневые или дублированные пути, подстановки, рекурсия, неявные текущие времена, не-FAT файловые системы, устройства, изменения ACL/ADS/прав собственности и автоматический выбор отклоняются. Предпросмотр пакета идентифицирует запись, но несколько обновлений каталогов FAT не заявляются как имеющие «все-или-ничего» откат. Создание устаревших профилей намеренно ограничено плоскими секторами, совместимыми с FAT, размером 512, 1024, 2048 или 4096 байт; носители с секторами 128/256 байт, GCR или переменное кодирование секторов, диски с аппаратной разметкой, не-FAT файловые системы, защищенные от копирования дорожки и захваты флюкса/битовых ячеек остаются рабочими процессами сохранения/инспекции RAW. Настройте `qemu-img` через **Tools → Preferences**, когда требуется конвертация виртуальных дисков. Просмотр NTFS/EXT/HFS/HFS+ только для чтения требует локально установленных Sleuth Kit `fls` и `icat`; необязательное контролируемое внедрение требует явно настроенных `ntfscp`/`ntfsls`/`ntfscat`, `debugfs`/`e2fsck` или, только для классического HFS, `hmount`/`hcopy`/`hls` для внедрения или `hformat` для проверенного создания. DiskForge никогда не скачивает, не монтирует и не запускает внешний конвертер молча. См. [FILESYSTEM_INJECTION.md](docs/FILESYSTEM_INJECTION.md) для точного контракта «copy-on-write» и неподдерживаемых путей.

## Инженерное качество

Проект включает автоматизированное покрытие для создания FAT, безопасного перемещения файлов и деревьев каталогов, безопасной материализации и очистки явно выбранной полезной нагрузки ZIP, консервативного восстановления кандидатов удалённых файлов FAT, инспекции IMD только для чтения и строгого экспорта RAW, инспекции TD0 только для чтения и строгого экспорта RAW с проверкой CRC, явных многопутевых обновлений метаданных FAT через CLI/SDK/пакет/десктоп, пакетной инвентаризации образов только для чтения с фильтрацией и отчетами JSON/CSV/HTML, а также расширенного редактирования метаданных, создания загрузочного ISO и инспекции El Torito, сохранения исходного шаблона BPB загрузчика, временного просмотра и очистки fixed VHD, планирования развертывания, консервативных отчетов по нулевым хвостам, нативных контрактов перетаскивания, полного графического редактирования пакетных рецептов и «предполетной» проверки без побочных эффектов, поведения предпросмотра/поиска/сохранения обратно документов, постраничного обхода каталогов, покрытия семи языков для полного рабочего пространства, публичных сессий API, портативных настроек, истории центра задач, постоянных представлений каталогов и предпочтений шрифтов, выбора темы, кроссплатформенной классификации оптических устройств, контрольных сумм, аутентифицированных пакетов образов, безопасного изменения размера, диагностики CRC GPT, жизненного цикла MBR, интеграции EXT только для чтения, самораспаковщиков, безопасности записи на устройство, экспорта каталогов и компактизации FAT на основе перестроения. pytest использует строгую конфигурацию, строгие проверки маркеров и трактовку предупреждений как ошибок; GUI также проверяется в среде без экрана. Непрерывная интеграция запускает те же критерии качества на Windows, Linux, macOS Intel и macOS Apple Silicon, а затем упаковывает каждую нативную цель. Теги версий сверяются с метаданными проекта, и уже существующий релиз приводит к сбою публикации, а не к перезаписи его артефактов.

```bash
QT_QPA_PLATFORM=offscreen pytest
QT_QPA_PLATFORM=offscreen python scripts/gui_smoke.py
QT_QPA_PLATFORM=offscreen python scripts/gui_i18n_smoke.py
```

См. [BUILDING.md](docs/BUILDING.md) для деталей сборки и релиза, [API.md](docs/API.md) для стабильной фасадной интеграции на Python, [VALIDATION.md](docs/VALIDATION.md) для принятия опциональных реальных ФС и оборудования UFI, [FILESYSTEM_INJECTION.md](docs/FILESYSTEM_INJECTION.md) для ограничений на опциональные записи NTFS/EXT/классического HFS и [COMPLETION_ACCEPTANCE.md](docs/COMPLETION_ACCEPTANCE.md) для поддающейся аудиту границы завершения. Примечание о визуальном «smoke»-тесте доступно в [gui_validation.md](artifacts/gui_validation.md).
