# DiskForge v0.8.0 实施前技术审计

> 本文记录当前源树的实现事实与下一步路径，不构成完成声明。

## 现有可复用基础

| 域 | 已有核心实现 | 当前缺口或风险 |
|---|---|---|
| FAT 创建与布局 | `create_fat_image()` 已支持 FAT12/16/32、显式媒体描述符、每磁道扇区数和磁头数，并在写入后补丁 BPB 几何。 | GUI/CLI 只公开了 MiB 大小、FAT 类型和卷标；尚无“从映像/扇区文件导入布局”服务、格式描述对象或受约束的自定义布局向导。 |
| FAT 编辑 | `FatImageFilesystem` 已提供注入、删除、重命名、属性、时间、卷标与文本回写所需的写入路径。 | 需要统一原子失败处理、容量预检和 FAT12/16/32 真实重开验收。 |
| 启动扇区 | `bootsector.py` 已有 512 字节大小检查、完整映像备份、结构化 FAT OEM/卷标/序列号编辑、原创模板和加载扇区文件的基础函数。 | 扇区文件导入未形成完整的受验证用户工作流；CLI/GUI 未完整暴露导入、消息编辑、预览差异与拒绝原因。 |
| ISO/El Torito | ISO 创作、启动目录检查和启动映像导出已经实现。 | 必须保持既有 ISO 只读，补齐可观察的启动属性导入/输出验证，而非尝试原地改写 ISO。 |
| 固定 VHD | 原生创建固定 VHD，验证页脚、计算虚拟尺寸；浏览会复制数据区并排除页脚。 | 不存在受控的 FAT-in-fixed-VHD 写入会话；任何实现都必须在数据区读写后重新验证页脚，或输出新 VHD 以避免破坏页脚。 |
| 外部虚拟磁盘格式 | `QemuImgConverter` 显式发现 `qemu-img`，可 JSON 检查和转换 VHDX/VMDK/QCOW2。 | 没有统一能力探测报告、取消期间的子进程管理、转换审计日志和格式特性限制说明；DMG 不在映射中。 |
| NTFS/EXT | Sleuth Kit 只读适配器负责浏览/提取；应用层已防止错误路由。 | 依赖发现、分区选择、诊断和真实样本覆盖需要加强。写入不应计入既定目标。 |
| 批处理 | `BatchRunner` 已使用可读 JSON，支持转换、验证、比较、缩放、提取、注入、容器和预演；图形设计器支持重新打开和逐项结果。 | 仅提取有集合源+顺序目的地流程；尚无映像清单格式、目录分卷注入、批次停止/跳过/重试的细粒度记录与可移植报告。实体设备操作应继续禁止于无人值守配方。 |
| 物理设备 | 跨平台设备枚举、流式读取、受 `ERASE` 保护的写入、可选写后比较、光学介质判别都存在。 | 仍是单设备操作；没有经审阅的设备采集队列、读取审计报告或控制器级格式化。后者不得假设可跨平台实现。 |

## 跨平台技术结论

1. **原生优先：** FAT、RAW、ISO、固定 VHD、启动扇区、MBR/GPT、设备流读写和批处理可在现有 Python/Qt 架构内闭合。
2. **适配器优先：** VHDX/VMDK/QCOW2 必须通过用户显式配置的转换器，界面和 CLI 都需要显示可用性、版本/格式特性、输入输出和失败日志。
3. **只读优先：** NTFS、EXT 和未经审计的 DMG 不应被猜测性写入。DMG 应先完成安全检查和受控只读适配可行性评估。
4. **硬件优先：** 控制器级软盘格式化、系统级挂载和专用驱动功能必须以平台能力检测、显式权限、真实硬件和风险确认作为前提；缺乏这些条件时只显示明确不支持。

## v0.8.0 的首个实施切入点

最适合先闭合的原生条目是 **M-04 与 M-05**：它们已有低层 FAT 几何和启动扇区服务，但缺少安全的数据模型、CLI/GUI 暴露、输入验证和回归。这一选择可以在不依赖外部工具或硬件的情况下获得真正可验证的能力增量，并为后续可启动 USB/MBR 输出工作流提供基础。
