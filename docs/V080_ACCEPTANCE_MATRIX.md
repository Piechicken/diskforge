# DiskForge v0.8.0 能力闭环验收矩阵

> **状态：实施前基线，不是发布声明。** 本矩阵将每项能力拆分为可发现的 GUI 路径、核心服务、命令行或结构化接口、成功/失败/取消回归，以及真实样本或真实设备边界。只有全部关闭后，v0.8.0 才允许发布。

## 完成判定规则

| 条件 | 必须满足的证据 |
|---|---|
| 核心行为 | 有明确、可调用的服务实现；不以菜单或占位对话框计为完成。 |
| 用户路径 | 在 GUI 中可发现，并给出输入、输出、风险与失败诊断。必要时同时提供 CLI/JSON。 |
| 安全边界 | 写入操作必须输出新文件、创建备份或要求前台确认；不安全、只读、缺少依赖与不支持格式必须明确拒绝。 |
| 自动化回归 | 覆盖成功、无效输入、取消或拒绝路径；pytest 严格模式下无警告。 |
| 真实验收 | 使用可公开的格式样本、用户提供样本或已连接设备进行验收；没有硬件时不得伪称已验证。 |
| 跨平台 | 由 Windows、Linux、macOS Intel 与 macOS Apple Silicon 的 CI 对对应可执行路径进行验证。 |

## 关闭顺序

1. **M-01 至 M-05：** 先闭合 RAW/FAT/ISO、自定义布局、启动与分区的原生能力。
2. **M-06 至 M-08、F-01：** 再审计并实现虚拟硬盘、受控转换及只读文件系统适配。
3. **A-01 至 A-02、D-01 至 D-03：** 完成可审计批处理、分发和实体介质工作流。
4. **F-02、U-01：** 对每轮功能进行文档式预览与跨平台发布回归加固。
5. 更新本矩阵、运行完整严格测试、真实样本验收和四平台 CI 后，才允许创建 `v0.8.0` 标签。

## 明确的非承诺

在本矩阵关闭前，不声称所有磁盘映像功能已经实现；不将外部工具、专用驱动、特定控制器或无真实硬件验证的能力称为原生跨平台功能；不对只读或不支持的写入路径进行猜测性修改。

## v0.8.0 当前证据状态

> **本节是当前工作树的如实状态，不把“可选外部适配”或“没有真实硬件的模拟回归”写成原生、全平台、已硬件验收的功能。** 当前严格测试为 `130 passed`，并已对两份用户提供的旧式 FAT12 软盘映像执行实际打开、枚举和 README 提取；详细记录见 `artifacts/v080_legacy_media_validation.txt`。

| 编号 | 当前状态 | 已有证据 | 仍然不能作出的声明 |

| M-01 | 已以真实样本复核 | 两份旧式 IMG/IMA 均识别为 FAT12 并成功枚举；用户鼠标驱动盘的 README 已提取为可读文本。 | 不代表任意损坏、加密或非 FAT 的历史介质都可修复。 |
| M-02 | 既有可编辑工作流保持回归 | FAT 创建、注入、删除、重命名、属性、时间、卷标和文本回写持续受严格回归覆盖。 | 不承诺非 FAT 文件系统写入。 |
| M-03 | 既有只读 ISO/El Torito 工作流保持回归 | ISO 创建、启动目录检查与导出维持只读边界。 | 不修改既有 ISO。 |
| M-04 | 本轮闭合 | 新增 FAT BPB 模板布局服务、CLI 和 GUI；有效布局可重建，无效扇区大小、FAT 数或几何被拒绝。 | 不接受不完整 BIOS 几何作为可重建模板。 |

因此，v0.8.0 可以准确表述为：**显著扩展了原生 FAT/固定 VHD 安全编辑、启动扇区导入、模板布局与只读设备采集，并为受限格式增加透明、用户显式的外部适配边界。它仍不是“任何格式、任何文件系统、任何硬件控制器均已原生实现”的产品。**
